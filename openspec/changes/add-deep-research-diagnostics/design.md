## Context

现有深研将细粒度 `currentStage` 和 `ResearchState` 返回给页面，但只持久化去重后的来源失败代码与泛化错误文案。页面仅显示单行状态，且 Run 与深研视图查询在终态仍持续轮询。详见 proposal.md 与 `deep-research-diagnostics` 规范。

## Goals / Non-Goals

**Goals:**

- 将细粒度执行阶段归并为稳定的五个用户流程节点。
- 在状态 JSON 中保存可安全展示的来源统计与失败诊断，使重试、刷新和历史查看一致。
- 将“没有可读公司资料”建模为需要用户决定的业务状态，而不是模型调用失败。

**Non-Goals:**

- 不放宽公网地址校验或绕过登录、验证码等页面限制。
- 不暴露供应商原始响应、密钥、请求内容或内部错误码。
- 不改造初筛流程或新增数据库表；深研状态继续保存在已有 JSON 状态中。

## Decisions

### 可选诊断字段与兼容读取

在 `ResearchState` 增加可选 `sourceReadSummary` 与 `diagnostic`。前者保存尝试、成功和按安全原因归并的失败数量；后者保存当前/失败阶段、面向用户的说明和建议动作。可选字段使旧 JSON 无需迁移即可继续解析，新的运行从创建时初始化。

错误分类在服务端完成：只将可判定的模型鉴权、限流、不可用、模型结果无效、来源访问和未知异常映射成固定用户文案。前端不解释异常对象或内部代码，避免展示边界随适配器变化。

### 无可读公司资料的分支

公司核实的搜索结果全部不可读时，编排器保存来源统计并将 Run 置为 `needs_attention`，保留既有补充和跳过命令。此分支不调用公司识别模型，避免空资料触发无意义的结构化请求。与“搜索工具本身失败”不同，后者仍按诊断失败处理。

### 五节点流程投影

页面从细粒度阶段计算五个节点：`resolve_company` 映射为核实公司，`company_snapshot` 与 `build_research_plan` 映射为研究公司，`gather_sources` 映射为收集岗位证据，`build_claims` 与 `assess_dimensions` 映射为核验证据与评估，`deep_research_report` 映射为生成报告。`needs_attention` 将核实公司显示为等待确认；诊断失败阶段显示失败，其他节点按顺序显示完成或未开始。

保留现有候选公司、补充线索、跳过、取消和重试交互；流程卡片在失败或等待确认时展示诊断中的行动建议。

### 活动状态刷新

`queued`、`running`、`waiting`、`needs_attention`、`cancelling` 维持轮询。其余 Run 状态返回 `false` 以停止 TanStack Query 的定时刷新；SSE 连接保留，用于事件导致的缓存失效。

## Risks / Trade-offs

- [历史状态没有读取统计] → 页面显示“暂无来源读取统计”，不推断失败原因。
- [单个高层节点覆盖多个细粒度阶段] → 失败文案补充当前可执行动作，避免把内部阶段名暴露给用户。
- [部分来源失败但仍有可读资料] → 继续研究并在最终 partial 报告的未知项中保留资料不足提示。

## Migration Plan

部署后新运行写入新增可选字段；旧运行按无诊断状态正常展示。回滚代码无需数据回滚，因为状态 JSON 的新增字段由旧代码忽略。
