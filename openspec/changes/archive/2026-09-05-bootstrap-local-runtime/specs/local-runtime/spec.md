## Purpose

定义求职研究应用在本机启动、持久化和执行后台任务时必须满足的基础行为，确保后续分析能力可以可靠运行、恢复并向界面反馈状态。

## ADDED Requirements

### Requirement: 本地应用可启动并报告健康状态
系统 SHALL 提供统一的本地开发入口，并在 API、数据库与后台任务执行器可用时报告健康状态。服务默认 MUST 仅监听本机回环地址。

#### Scenario: 所有运行时组件启动成功
- **WHEN** 开发者执行项目约定的本地开发命令
- **THEN** Web、API 和后台任务执行器均可用，健康检查返回成功及各组件状态

#### Scenario: 必要组件初始化失败
- **WHEN** 数据库迁移或后台任务执行器初始化失败
- **THEN** 健康检查不得报告完全健康，并提供可定位失败组件的错误信息

### Requirement: 数据库模式可重复迁移
系统 SHALL 在应用启动前应用尚未执行的版本化数据库迁移，并记录迁移版本。同一组迁移被重复执行时 MUST 保持数据库模式一致。

#### Scenario: 首次启动空数据库
- **WHEN** 应用连接到不存在或没有表结构的本地数据库
- **THEN** 系统创建数据库并依次应用全部迁移

#### Scenario: 再次启动已有数据库
- **WHEN** 应用连接到已应用当前版本迁移的数据库
- **THEN** 系统不重复修改已完成的迁移，并正常启动

### Requirement: 后台作业具有持久化生命周期
系统 SHALL 持久化后台作业的类型、输入引用、状态、尝试次数、时间戳、进度和错误摘要。作业状态 MUST 至少覆盖 queued、running、succeeded、failed 与 cancelled，且终态不得被再次执行。

#### Scenario: 作业执行成功
- **WHEN** 执行器领取 queued 作业并成功完成处理
- **THEN** 作业依次进入 running 和 succeeded，结果引用与完成时间被持久化

#### Scenario: 查询作业状态
- **WHEN** 客户端按作业 ID 查询一个存在的作业
- **THEN** 系统返回当前状态、进度、尝试次数及可公开的错误信息

### Requirement: 作业领取在并发下保持唯一
系统 SHALL 通过原子领取和有限期租约保证同一个作业在同一时刻最多由一个执行器处理。执行器 MUST 在长任务期间续租，且只有租约持有者可以提交本次执行结果。

#### Scenario: 多个执行器同时领取
- **WHEN** 两个执行器同时尝试领取同一个 queued 作业
- **THEN** 只有一个执行器获得租约并开始执行

#### Scenario: 过期执行器迟到提交
- **WHEN** 原执行器的租约已过期且作业已被其他执行器重新领取
- **THEN** 系统拒绝原执行器提交状态或结果

### Requirement: 中断作业可在重启后恢复
系统 SHALL 在启动时识别租约已过期的 running 作业，并根据剩余尝试次数重新排队或标记失败。单个作业 MUST 有有限的最大尝试次数，默认最多执行三次。

#### Scenario: 可重试作业的执行器异常退出
- **WHEN** 应用重启并发现 running 作业租约已过期且仍有剩余尝试次数
- **THEN** 系统将作业重新置为 queued，并记录恢复事件

#### Scenario: 作业耗尽尝试次数
- **WHEN** 作业再次失败且已达到最大尝试次数
- **THEN** 系统将作业标记为 failed，不再自动执行，并保留最终错误摘要

### Requirement: 用户可以取消未完成作业
系统 SHALL 接受对 queued 或 running 作业的取消请求。执行器 MUST 在安全检查点响应取消；已经进入终态的作业不得因取消请求改变结果。

#### Scenario: 取消排队中的作业
- **WHEN** 客户端取消一个 queued 作业
- **THEN** 作业立即进入 cancelled，且执行器不得再领取它

#### Scenario: 取消执行中的作业
- **WHEN** 客户端取消一个 running 作业
- **THEN** 系统记录取消请求，执行器在下一个安全检查点停止并将作业置为 cancelled

### Requirement: 客户端可订阅并补放作业事件
系统 SHALL 为单个作业提供有序的实时事件流，覆盖状态、进度、完成与失败事件。事件 MUST 被持久化并具有单调递增标识，使断线客户端能够从最后已接收事件之后继续订阅。

#### Scenario: 在线接收进度
- **WHEN** 客户端订阅一个执行中的作业
- **THEN** 新的状态和进度事件按持久化顺序发送给客户端

#### Scenario: 断线后继续订阅
- **WHEN** 客户端携带最后已接收事件标识重新建立订阅
- **THEN** 系统先补发该标识之后的历史事件，再继续推送新事件，且不补发更早事件

### Requirement: 测试任务不依赖外部模型服务
系统 SHALL 提供遵循模型调用边界的确定性测试替身，使后台作业成功、失败、延迟和取消路径能够在无网络、无密钥环境中验证。

#### Scenario: 使用测试模型执行作业
- **WHEN** 测试为后台处理器注入确定性模型替身
- **THEN** 作业无需访问外部服务即可产生预设结果或错误
